# FinSight — Data Dictionary & Schema Specification

**Document Version:** 1.0.0  
**Target Database:** PostgreSQL 15+  
**Schema:** `public`  
**System:** FinSight Transaction Intelligence Platform  

---

## 1. Schema Architecture Overview

FinSight organizes data into logical functional zones to ensure end-to-end auditability and separation between landing data, cleaned facts, dimensions, and operational audit records:

| Table Name | Layer | Description | Grain (1 row represents...) |
| :--- | :--- | :--- | :--- |
| `stg_transactions` | Staging | Ephemeral raw input table mirroring incoming CSV structure. | One raw transaction record from the source file. |
| `fct_transactions` | Fact | Validated, cleaned transaction records. | One approved, validated financial transaction event. |
| `fct_risk_evaluations` | Fact | Risk scores, tiers, and reason codes generated by the rule engine. | One risk evaluation corresponding 1:1 to a validated transaction. |
| `dim_customers` | Dimension | Customer profile attributes, KYC status, and country of origin. | One unique registered customer account. |
| `dim_merchants` | Dimension | Merchant business attributes, MCC classification, and risk tier. | One unique merchant account or terminal. |
| `dq_quarantine_records` | Audit / Quarantine | Records rejected during validation with failure reasons. | One failed transaction attempt that violated data contracts. |
| `dq_audit_log` | Audit | Execution metadata for batch runs and data quality statistics. | One pipeline execution batch run. |

## 2. Table Specifications

### 2.1. `stg_transactions` (Staging Layer)
- **Description**: Raw landing table for incoming batch files. No strict constraints applied to facilitate bulk load and debugging.
- **Grain**: One raw transaction row.

| Column Name | Data Type | Nullable | Description | Example Value |
| :--- | :--- | :---: | :--- | :--- |
| `raw_id` | `BIGSERIAL` | N (PK) | Auto-incrementing staging row identifier. | `1001` |
| `transaction_id` | `VARCHAR(64)` | Y | Transaction ID as provided in the raw source. | `TXN_98234123` |
| `customer_id` | `VARCHAR(64)` | Y | Customer identifier from raw payload. | `CUST_00492` |
| `merchant_id` | `VARCHAR(64)` | Y | Merchant identifier from raw payload. | `MERC_7712` |
| `amount` | `VARCHAR(32)` | Y | Transaction amount (stored as string prior to validation). | `149.50` |
| `currency` | `VARCHAR(8)` | Y | Currency ISO code. | `USD` |
| `timestamp` | `VARCHAR(32)` | Y | Timestamp string as provided by source. | `2026-03-15 14:32:00` |
| `payment_method` | `VARCHAR(32)` | Y | Payment rail/channel used. | `CREDIT_CARD` |
| `status` | `VARCHAR(32)` | Y | Transaction outcome status. | `SUCCESS` |
| `country` | `VARCHAR(8)` | Y | Two-letter ISO country code of transaction origin. | `US` |
| `mcc` | `VARCHAR(8)` | Y | Merchant Category Code. | `5411` |
| `ingestion_batch_id` | `VARCHAR(64)` | N | Unique UUID of the ingestion run. | `BATCH_20260315_01` |
| `ingested_at` | `TIMESTAMPTZ` | N | System timestamp when record landed in staging. | `2026-03-15 14:35:10Z` |

### 2.2. `fct_transactions` (Validated Fact Layer)
- **Description**: Curated, validated fact table storing all clean transactions suitable for financial analytics.
- **Grain**: One unique, validated transaction event.

| Column Name | Data Type | Nullable | Key | Constraints / Validation | Description |
| :--- | :--- | :---: | :---: | :--- | :--- |
| `transaction_id` | `VARCHAR(64)` | N | PK | Unique, non-null, format `TXN_[A-Za-z0-9]+` | Primary transaction identifier. |
| `customer_id` | `VARCHAR(64)` | N | FK | References `dim_customers(customer_id)` | Unique identifier of transacting customer. |
| `merchant_id` | `VARCHAR(64)` | N | FK | References `dim_merchants(merchant_id)` | Unique identifier of receiving merchant. |
| `amount` | `NUMERIC(12,2)`| N | - | `> 0.00` AND `<= 1,000,000.00` | Financial value of transaction in native currency. |
| `currency` | `CHAR(3)` | N | - | ISO-4217 code (`USD`, `EUR`, `GBP`, `CAD`, `AUD`, `INR`) | Currency code. |
| `timestamp` | `TIMESTAMPTZ` | N | - | Must be valid datetime `<= CURRENT_TIMESTAMP` | Exact date and time transaction was initiated. |
| `payment_method` | `VARCHAR(32)` | N | - | IN (`CREDIT_CARD`, `DEBIT_CARD`, `UPI`, `BANK_TRANSFER`, `DIGITAL_WALLET`) | Rail utilized for processing. |
| `status` | `VARCHAR(20)` | N | - | IN (`SUCCESS`, `FAILED`, `PENDING`, `CANCELLED`, `REVERSED`) | Final transactional status. |
| `country` | `CHAR(2)` | N | - | ISO-3166-1 alpha-2 format | Transaction origin country code. |
| `mcc` | `CHAR(4)` | N | - | 4-digit standard MCC format | Merchant Category Code. |
| `ingestion_batch_id` | `VARCHAR(64)` | N | - | Non-null | Ingestion pipeline batch tracking identifier. |
| `created_at` | `TIMESTAMPTZ` | N | - | Default `CURRENT_TIMESTAMP` | Record persistence timestamp. |

---

### 2.3. `fct_risk_evaluations` (Risk Scoring Fact Layer)
- **Description**: Stores deterministic risk evaluations, risk score breakdowns, and human-readable reason codes generated by the risk rules engine.
- **Grain**: One risk evaluation per validated transaction.

| Column Name | Data Type | Nullable | Key | Constraints / Validation | Description |
| :--- | :--- | :---: | :---: | :--- | :--- |
| `evaluation_id` | `BIGSERIAL` | N | PK | Auto-incrementing primary key | Unique risk evaluation identifier. |
| `transaction_id` | `VARCHAR(64)` | N | FK / UK | References `fct_transactions(transaction_id)` | Transaction evaluated (1:1 relationship). |
| `risk_score` | `INT` | N | - | Range: `0` to `100` | Composite risk score calculated across rules. |
| `risk_tier` | `VARCHAR(16)` | N | - | IN (`LOW`, `MEDIUM`, `HIGH`) | Categorical risk band based on score thresholds. |
| `action_recommended`| `VARCHAR(32)` | N | - | IN (`AUTO_APPROVE`, `MANUAL_REVIEW`, `FLAG_SUSPICIOUS`) | Recommended operational intervention. |
| `triggered_rule_count`| `INT` | N | - | `>= 0` | Total number of individual risk rules fired. |
| `triggered_rules` | `TEXT[]` | N | - | Array of string Rule IDs | Array of fired rule codes (e.g. `{'RULE_001', 'RULE_002'}`). |
| `reason_codes` | `JSONB` | N | - | Valid JSON structure | Human-readable explanation messages for audit review. |
| `is_flagged` | `BOOLEAN` | N | - | `TRUE` if `risk_score >= 70` else `FALSE` | Boolean flag indicating high-risk status. |
| `evaluated_at` | `TIMESTAMPTZ` | N | - | Default `CURRENT_TIMESTAMP` | Timestamp when risk evaluation was executed. |

### 2.4. `dim_customers` (Customer Dimension)
- **Description**: Dimensional attributes describing account holders.
- **Grain**: One unique customer.

| Column Name | Data Type | Nullable | Key | Constraints | Description |
| :--- | :--- | :---: | :---: | :--- | :--- |
| `customer_id` | `VARCHAR(64)` | N | PK | Unique string | Customer identifier. |
| `customer_name` | `VARCHAR(128)`| N | - | Anonymized synthetic string | Customer full name. |
| `customer_tier` | `VARCHAR(16)` | N | - | IN (`STANDARD`, `PREMIUM`, `VIP`) | Account loyalty tier. |
| `kyc_status` | `VARCHAR(16)` | N | - | IN (`VERIFIED`, `PENDING`, `REJECTED`) | Identity verification status. |
| `home_country` | `CHAR(2)` | N | - | ISO-3166-1 alpha-2 | Customer country of primary residence. |
| `account_created_at`| `TIMESTAMPTZ`| N | - | Valid historical datetime | Account registration timestamp. |

---

### 2.5. `dim_merchants` (Merchant Dimension)
- **Description**: Dimensional attributes describing merchant businesses.
- **Grain**: One unique merchant.

| Column Name | Data Type | Nullable | Key | Constraints | Description |
| :--- | :--- | :---: | :---: | :--- | :--- |
| `merchant_id` | `VARCHAR(64)` | N | PK | Unique string | Merchant identifier. |
| `merchant_name` | `VARCHAR(128)`| N | - | Anonymized synthetic string | Registered business name. |
| `mcc` | `CHAR(4)` | N | - | 4-digit code | Merchant Category Code. |
| `mcc_description` | `VARCHAR(128)`| N | - | Descriptive category | Industry name (e.g. `Grocery Stores`, `Gambling`). |
| `merchant_country` | `CHAR(2)` | N | - | ISO-3166-1 alpha-2 | Registered country of business operation. |
| `is_high_risk_mcc` | `BOOLEAN` | N | - | Derived from risk registry | Boolean flag indicating high-risk merchant category. |

---

### 2.6. `dq_quarantine_records` (Data Quality Quarantine)
- **Description**: Stores raw payloads that failed validation checks, preserving the exact data for audit and remediation.
- **Grain**: One rejected transaction record.

| Column Name | Data Type | Nullable | Key | Description |
| :--- | :--- | :---: | :---: | :--- |
| `quarantine_id` | `BIGSERIAL` | N | PK | Unique quarantine event ID. |
| `ingestion_batch_id`| `VARCHAR(64)` | N | - | Ingestion batch identifier. |
| `raw_record_payload`| `JSONB` | N | - | Complete original JSON representation of the rejected row. |
| `error_code` | `VARCHAR(64)` | N | - | Machine-readable validation error code (e.g. `ERR_NULL_CUSTOMER_ID`). |
| `error_message` | `TEXT` | N | - | Detailed human-readable validation failure reason. |
| `quarantined_at` | `TIMESTAMPTZ` | N | - | System timestamp when record was quarantined. |

---

### 2.7. `dq_audit_log` (Pipeline Execution Audit)
- **Description**: Audit log tracking summary statistics of each pipeline execution batch.
- **Grain**: One pipeline execution run.

| Column Name | Data Type | Nullable | Key | Description |
| :--- | :--- | :---: | :---: | :--- |
| `batch_id` | `VARCHAR(64)` | N | PK | Unique batch execution ID. |
| `source_file` | `VARCHAR(256)`| N | - | Filename of the ingested dataset. |
| `total_rows_read` | `INT` | N | - | Total count of rows parsed from source. |
| `clean_rows_loaded`| `INT` | N | - | Total count of rows passing validation and loaded to facts. |
| `quarantine_rows` | `INT` | N | - | Total count of rows rejected to quarantine. |
| `duplicate_rows` | `INT` | N | - | Total count of duplicate rows detected and dropped. |
| `execution_status` | `VARCHAR(20)` | N | - | IN (`SUCCESS`, `PARTIAL_SUCCESS`, `FAILED`). |
| `started_at` | `TIMESTAMPTZ` | N | - | Execution start timestamp. |
| `completed_at` | `TIMESTAMPTZ` | N | - | Execution end timestamp. |
| `duration_seconds` | `NUMERIC(8,2)`| N | - | Total elapsed runtime in seconds. |
